# 基于不可变历史实现长期项目维护

## 哲学

### 记忆影响的不对称性

- 包含有效信息：小优。
- 包含无效信息：小劣。稍微浪费了 token，但不会影响后续工作。
- 丢失信息：小劣。只要保存了原始记录，可以重新查找发现出来。
- 包含错误信息：大劣。误导可能导致项目方向产生偏移。

### Inference-time RL

- 必须有 Reward 反馈
- 反馈必须干预 Agent 行为
- 不能新训练模型，只能依靠 LLM critic 改动

### Temporal Information Bottleneck

必须要限制记忆容量到能作为 Agent 提示词起点的范围，目的是提高有效信息密度。

### Replay Learning

保留完整数据分布：不同时期的历史，学习形式上要等权参与记忆过程

学习形式上偏向新数据，可能导致灾难性遗忘与焦点漂移。

### VCS compatible

需要支持分支合并

## 架构介绍

### 摘要树

每项任务完成后，提交一个总结文件 $h_t$，提交完成后不可更改。

建立度为 $k$ 的摘要树，使用整棵树作为 $m_t$ 的数据结构：

- 每个文件长度不超过 $L$，由头部元数据以及正文陈述列表组成
- 树最底层节点为依序排列的 $h_t$，尚未发生的部分为空
- 将每一层树节点切分为长度为 $k$ 的段，每段摘要为一个新文件，作为上一层的节点
- 摘要文件陈述的来源可能为：1.原样转述子节点陈述；2.结合多个子节点陈述新产生

支持写操作：

- Commit: 记录最新提交的 $h_t$，然后更新所有相关的上层摘要
- Fix: 将一个摘要节点的子树标记为不可变。常用于子树填满后。
- Squash merge: 为末尾一段提交的 $h_t$ 重建一棵不可变子摘要树，回滚到开始位置，然后 Fix 并 Commit 树根

支持读操作：

- Root: 找最高层非空节点。其内容适合作为初始送入 Agent 的线索
- Expand: 返回给定节点的子节点列表

#### 分组管理

在每个提交文件的元数据中，可以指定若干 tag.
系统可以为每个 tag 对应的提交子集单独建一棵摘要树，用于特定领域的检索。

### 提交文件中的评价信号

#### 评价摘要中的陈述是否有误

新节点任务读取树中陈述后，如果发现过时或者有误导，可以在提交文件中给出评价。
后续创建摘要时，既可以根据评价判断是否将一条陈述保留到高层中。

如果评价频率高，说明这条陈述对应的话题可能较为关键。
后续创建摘要时，可以根据针对此话题补充陈述。

#### 评价历史任务的完成结果对未来的影响

新节点任务发现之前的任务成果有坑时，可以在提交文件中给出评价。
后续创建摘要时，可以根据评价创建反思性陈述。

### Agent 读取

渐进查询：Agent 读取时，可以根据需要逐层展开

关键词查询：所有提交文件与摘要文件都以文本形式存储，如有必要，可以由各种方式 Agentic Search。
